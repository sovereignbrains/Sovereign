# Сравнение клиентов: первый прогон (17.10.2026)

Sovereign 0.5.22 против Hiddify 4.1.1, v2rayN 7.25.6, Happ 4.5.4 и INCY desktop 3.8.10.
Всё скачано с официальных GitHub-репозиториев, sha256 сверены с digest релиза.
Прогон черновой: по одному замеру на клиента, без чередования. Следующий будет по кругу,
по 5 раз, плюс Hysteria 2.

## Стенд

- Сервер: VPS в Хельсинки (1 vCPU, 4 ГБ), официальный sing-box 1.14.3, `server-setup.sh`:
  VLESS + Vision + REALITY на 443/tcp, Hysteria 2 на 8443/udp. Только для замеров, чужого трафика нет.
- Клиент: Windows 11 IoT Enterprise LTSC 2024, Ryzen 5 5600X, Wi-Fi AX210, домашний канал ~250 Мбит/с.
- Все клиенты в режиме TUN (весь трафик системы), окно спрятано в трей, сервер VLESS REALITY.
- Ссылка у всех одна. С `fp=chrome` Xray-клиенты к REALITY-серверу на sing-box проходят
  примерно в 4 из 12 соединений (sing-box-клиенты — 15 из 15), с `fp=firefox` — 12 из 12.
  Sovereign и Hiddify мерились с `fp=chrome`, v2rayN, Happ и INCY — с `fp=firefox`.

## Что мерили и как

- `measure.ps1` — сумма памяти (private bytes) всех процессов клиента при подключении, CPU за
  60 с простоя, выход (ipify), WebRTC (STUN-запрос к stun.l.google.com), утечка DNS (bash.ws),
  задержка (20 новых соединений: TCP, TLS, первый байт), скачивание 100 МБ с Hetzner.
- `killswitch.ps1` — зонд каждые 250 мс спрашивает, с какого адреса виден компьютер:
  - **падение ядра** — процесс ядра убивается (`Stop-Process -Force`), смотрим 25 с;
  - **сервер пропал** — порты сервера закрываются на 20 с iptables на самом сервере (открываются
    его же таймером), смотрим ещё 40 с.
  Утечка — любой ответ не с адреса сервера.
- `run.ps1` — всё одним запуском от администратора. `cpu-split.ps1` — CPU по процессам.

Скорость и задержка в этом прогоне — один замер на клиента при шумном канале, выводов по
ним не делаем; по памяти, CPU и падению ядра разница больше шума.

### Падение ядра — главное

Sovereign держит туннель службой и kill switch (фильтры WFP): ядро упало — трафик закрыт,
пока служба не поднимет ядро; ни один запрос не ушёл мимо. У Hiddify, v2rayN и Happ после
падения ядра весь трафик за доли секунды идёт напрямую с домашнего адреса, а программа
остаётся в трее, будто всё работает.

### INCY не открывает сайты в режиме TUN

В настройках `enableFakeDNS = false`, но в конфиг Xray всё равно попадает `fakedns` с пулом
`240.0.0.0/4`. Windows не соединяется с адресами класса E (`connect` падает сразу), поэтому
сайты по имени не открываются, по IP — открываются. А когда процесс INCY убит, он оставляет
в системе свой DNS (198.18.0.2) на Wi-Fi — интернет по именам не работает и без него, пока DNS не
сбросить вручную.

## Что недействительно в `results/`

- `sovereign-killswitch.jsonl`, первая строка, «сервер»: блокировка брандмауэром Windows —
  фильтры WFP Sovereign её перебивают; заменено блокировкой на сервере (вторая строка).
- `hiddify-killswitch.jsonl`, строки 1–2, «сервер»: в первой Hiddify уже был убит, во второй
  команда «открыть» шла через закрытый туннель. Действительна третья.
- `v2rayn-killswitch.jsonl`, первая строка, «ядро»: имена процессов ушли одной строкой, ничего
  не убито. Действительна вторая.
- `happ-killswitch.jsonl`, первая строка, «сервер»: Xray уже был убит. Действительна вторая.
